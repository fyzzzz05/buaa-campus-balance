# 校园余额

在 Mac 上查看北航校园卡、校园网流量和宿舍电费。一个面板，了解余额和近期使用情况。macOS 应用使用 Swift 实现，不内置 Node.js 运行时。

## 功能

- **校园卡**：查看余额和消费流水，按天展示消费金额。
- **校园网**：查看流量余额、本期用量和按学校结算日汇总的流量。
- **电费**：分别查看照明与空调余额，以及根据历史余额变化估算的每日消耗。
- **趋势**：点击左侧项目或使用上下方向键切换；支持柱状图和折线图。
- **电表设置**：填写自己的照明和空调电表号，可选接入自己的电费监控历史。

## 安装与使用

1. 从 [Releases](https://github.com/fyzzzz05/buaa-campus-balance/releases/latest) 下载 `CampusBalance-v版本号-macOS-arm64.dmg`，打开后将应用拖入「应用程序」。需要 Apple 芯片 Mac 和 macOS 13.5 或更新版本。
2. 在能够访问学校服务的网络中登录。可以在应用内填写统一身份认证账号和密码，或者选择「打开学校统一认证」到学校页面登录。
3. 点击右上角「电表号」，填写自己的照明和空调电表号。电表号可通过北航总务公众号查询；目前不能仅凭楼栋和房间自动查找。

学校页面登录不会将密码交给应用，因此不会自动连接校园网。若要查看校园网流量，可使用账号密码方式登录，并在密码相同时勾选「校园网使用相同密码」。

应用尚未使用 Apple Developer ID 签名和 Apple 公证，首次打开可能出现 macOS 验证提示。

## 数据说明

- 校园卡消费来自学校流水，校园网用量按学校结算数据统计。数据更新可能有延迟。
- 电费图表根据相邻日期的余额减少量估算，充值或缺少记录时不能等同于实际消费流水。
- 电表查询优先使用 HTTPS；连接失败或超时时尝试 HTTP，并在余额旁注明「HTTP 查询」。支持学校页面的「电价／电哈哈价」「地址／地哈哈址」字段。
- 学校电表服务不可用时，可在电表设置的「其他设置」中填写自己的 GitHub 用户名，读取该用户 `buaa-electricity-monitor` 仓库中公开的 `main/data/history.csv`。历史记录的电表号必须与设置一致。

## 隐私与登录

应用的服务只监听本机 `127.0.0.1`，请勿直接暴露到公网。账号密码不会写入项目文件；选择自动重新登录后，密码会保存在 macOS 登录钥匙串，在学校会话失效时按需读取。退出面板会删除保存的密码；学校要求验证码或其他验证时仍需手动登录。

电表设置和本地数据保存在当前用户的 `~/Library/Application Support/CampusBalance`。不同账号的设置相互独立。

## macOS 快捷键

- `⌘W`：关闭窗口，保留当前登录；点击 Dock 图标重新打开。
- `⌘Q`：退出应用。
- `⌘M`：最小化窗口；`⌘H`：隐藏应用。
- `⌘A / C / V / X`：全选、拷贝、粘贴、剪切。
- `⌘Z / ⇧⌘Z`：撤销、重做。

「帮助 → 打开诊断日志」可直接在 Finder 中定位查询日志。

## macOS 桌面小组件

macOS 14 及以上可添加小号「校园余额」组件，点击底部图标切换校园卡、校园网、照明和空调余额。在带组件的应用中登录并勾选自动重新登录后，后台任务每天 8:30 尝试更新；电脑休眠、网络或学校服务不可用时，更新可能延迟。失败时保留上次成功获取的余额及其更新时间。

组件只读取本机缓存的余额。数据通过只监听 `127.0.0.1` 的进程提供，使用安装时生成的密钥校验；账号密码保存在钥匙串，不发送给组件。退出应用账户会关闭后台任务并清除组件数据。构建组件需要完整 Xcode：

```sh
./desktop/widget/build-with-widget.sh
```

版本号记录在 `VERSION`，默认构建到 `outputs/校园余额-v版本号.app`；也可通过 `APP_VERSION` 和脚本参数指定版本及输出位置。更新时先确认新版本、组件和后台任务正常，再将后台任务切换到新版本并清理被替代的旧应用。每次版本更新用 Git 提交记录。

## 本地开发

### 查询故障排查

面板会区分连接失败、请求超时、HTTPS 证书或握手失败、HTTP 错误、登录失效、流量单位无法识别、电表字段缺失及表号／类型不匹配。流水查询失败不影响已获取的余额；使用电费历史余额兜底时，会注明实时查询失败。

macOS 应用及本机网页模式的诊断日志位于 `~/Library/Logs/CampusBalance/diagnostics.ndjson`。每行是一条 JSON，记录时间、错误码、查询阶段、固定服务地址、协议与端口，以及适用的 HTTP 状态码或字段名。照明和空调分别标记为 `lightingMeter`、`airMeter`。接口响应的 `diagnostic`、`historyDiagnostic`、`fallbackDiagnostic` 分别对应余额失败、流水失败和历史兜底；`transportDiagnostic` 保留 HTTPS 失败后改用 HTTP 的原因。

日志不记录账号、密码、Cookie、原始页面、完整认证 URL 或电表号；单个日志达到 256 KiB 后轮换，最多保留当前文件及一个 `.1` 备份。例如 `FIELD_MISSING` 配合字段“电价”表示解析规则需要核对，`CONNECTION_FAILED` 配合电费服务 HTTPS 443 表示连接失败，不能仅据此断定学校停机。

macOS 应用需要完整版 Xcode 和可以访问学校服务的网络。运行原生测试：

```sh
./tests/run-native.sh
```

仓库仍保留网页开发模式；运行网页模式和现有 JavaScript 测试需要 Node.js 22 或更新版本：

```sh
npm ci
./start-web.command
```

打开 `http://127.0.0.1:4174`。macOS 用户也可以双击 `start-web.command`。网页模式可以使用账号密码登录；跳转学校页面后自动返回应用的登录方式仅在 macOS App 中提供。

运行测试：

```sh
npm test
```
